# 架构约定

## 数据库封装

需要封装，但不是用一个跨业务的 CRUD 代理。正确边界是：

1. 页面只处理交互状态，通过 `miniprogram/services/cloud.js` 调用命名明确的云函数操作。
2. 云函数负责调用者身份、权限、输入校验、业务规则和错误映射。
3. 仓储模块是唯一可以访问 `cloud.database()` 的位置。
4. 每个集合绑定一个业务领域，不允许页面按集合名动态查询。

例如餐厅领域可在需求确定后建立 `restaurants` 云函数与仓储；订单领域建立独立的 `orders` 云函数与仓储。两个领域不共享通用的“更新任意记录”接口。

## 配置边界

`miniprogram/config/project.js` 只能存环境 ID、公开标识和功能名称。所有 AK/SK、第三方密钥、数据库密码仅存放在 CloudBase 云函数环境变量或受保护的部署变量中。

## 已清理的测试资源

本地检测页面与 `toolboxFunctions` 已删除。此前部署到 CloudBase 的同名云函数和 `toolbox_checks` 测试集合是远端资源，不会因删除本地文件自动消失；在确认不再需要后，应在 CloudBase 控制台手动删除。
